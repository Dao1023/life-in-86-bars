# 一个上海人的一生，每年要花多少钱 · v6（数据 v4-rebuild-2026-11）

**怎么打开**：直接双击 `viz/lifecycle.html`（单文件、约 230 KB，CSS / JS / 数据全部内联，无 CDN、无字体、无图表库，断网可用）。

**重新生成**：`cd viz && python build.py`。脚本读 `../data/shanghai_lifecycle.json`（必读）、`../data/shanghai_lifecycle_household.json`（可选）、`../data/sensitivity_kindergarten.json` / `sensitivity_a5.json` / `sensitivity_longtermcare.json` / `sensitivity_retirement_glide.json` / `sensitivity_childcare.json`（可选），注入 `template.html` 的 `/*__DATA__*/` 占位符；幂等。任何可选文件缺席都不报错，只隐藏对应控件。

**这一版的数据是 `v4-rebuild-2026-11`**：v2 那个「60 岁退休掉 10.4%」被复核判定是硬乘出来的装饰（去掉乘数只剩 −0.49%），v3 已删除，改成五年 glide。页面上的每个数字都从 JSON 现算，没有一处硬编码。旧版截图在 `viz/archive/`。

## 三、交互清单

- **悬停**：竖高亮带 + 顶部浮动 tooltip（年龄、合计、8 类金额与占当年比，两列）；移出消失。
- **点击柱子**：钉住该年 → 右侧详情卡；再点取消。**键盘**：Tab 到任意柱（焦点虚线框 + 读屏 live 文本）→ Enter 钉住，←/→ 换年。
- **图例 solo**：点某类 → 其余 7 类淡出到 8% 并显示该类当年绝对额；再点恢复。
- **视图**：金额 ↔ 占比（每根柱归一到 100%，y 轴 20% 网格；`prefers-reduced-motion` 下无过渡）。
- **情景**：低 / 基准 / 高，300ms 过渡；判断句与峰值标记锚定基准情景（不随情景漂移成两个数）。
- **敏感性**：幼儿园（公办 5,000 / 民办 12,000）、老年折减（基准 1.00 / 旧版 0.72）、长期照护（居家 / +1,500 / +3,000），三段都是独立开关、不做平滑过渡。下面两行只给汇总、不画曲线：**入托率三档**（2→3 岁 +16.4% / +8.6% / +1.8%，30–39 岁三档只差 0.06%——局部参数）与 **退休缓坡端点 ρ_end**（0.85 / 0.90 / 0.95 → 五年 −17.3% / −12.4% / −7.5%，全表平移）。
- **口径**：人均（0–85）↔ 每户（户主 22–85）。同时更换横轴范围与刻度、y 轴刻度、单位、图注、关键数字条、阶段色带、注释集合；0–17 斜纹只在人均出现；每户口径下敏感性整行隐藏，并在判断句下方出现一条**户构成警告**（一人户 11% vs 七普 28%，水平与形状都不代表真实户分布）。
- **幼儿园 / 老年折减 / 长期照护**：叠加在情景之上的独立开关，**切换不做平滑过渡**——目的就是让跳变被看见。三个开关都不改峰位（峰恒在 46 岁），这本身就是结论：**换幼儿园口径改不动峰的位置**。数据文件缺席时该分段整体隐藏，不显示禁用按钮。
- **显示注释**：关掉后只剩曲线与网格。

## 五、已知视觉问题与限制

1. **每户 8 条注释挤在 46–53 岁**：46/47/52/53 要三层错开，46 岁那条标题被截短成「46 岁 · 户均峰值」（完整句在悬停 `<title>` 里）。
2. **每户 y 轴顶部留白**：上限按当前情景 `ceil(max×1.05/5000)`，基准下是 185,000，最上一根网格线标到 18 万——顶线被 46 岁柱子贴近，但 185,000 这条本身没有刻度标签（避免多一个非整数档）。
3. **23 岁的「+14%」只在悬停与正文里，不在图上的短标签里**：标签预算 148 px，`23 岁 · 毕业工作 · 居住 39.7%` 放不下，图上只留「23 岁 · 毕业 · 居住 39.7%」。
4. **1024 宽下 0/3/6 岁三条注释的引线挨得近**，不重叠但密度偏高。
5. **390 宽不重排图表**，只做横向滚动（按规格「手机不要求完美但不要崩」）。
6. **18 岁虚线只标口径切换**，不代表金额，所以配了一行小字，避免被当成网格线。
7. `viz/harmonised_shares_by_age.png` 是数据侧产物，本页未引用。
8. **主张强度**：46 岁是成年段年龄梯度 φ 的 argmax，属参数设定而非实测发现，所以判断句写「模型里最贵的一段在 46 岁前后」，不写「最贵的一年是 46 岁」；`meta.peak_to_trough` 已是 2.04，与现算一致。

## 六、口径与数据（与方法论面板同一套话）

- **没有任何一格是官方分年龄观测值。** 上海 2024 官方只发布全年龄八大类总额（54,980 元/人/年）。
- 年龄形状分三段：0–17 岁逐年篮子（吃、穿、用、学费、医疗各自绝对额）；18–22 岁独立构造的大学成本（学费 + 住宿 + 生活费）；23–85 岁「户均消费 × 成员份额调整 φ(a) × 退休缓坡 ρ(a)」。八类年龄梯度由 12 个 knot 给出，最后用 IPF 把行列和压回官方八类与 54,980 元（单格压缩上限 15%，实测最大 6.09%）。
- 0–17 岁是**家庭代付**，18–22 岁学费 + 生活费，23 岁起本人消费。18 岁那个 −7.8% 的台阶一半是口径切换；22→23 岁则相反，是 +14.0% 的**向上**的缝（一半是毕业后的真实变化，一半是「住校 → 租房」）。
- **60 岁的坡是行为假设，不是观测**：v2 的 ρ=1−0.10·smoothstep(59,60) 是一个硬乘数，去掉后只剩 −0.49%；v3 改成五年 glide（ρ 从 1.00 线性降到 0.90），单年 −3.5%、五年 −12.4%。
- **退休缓坡不是一条观测曲线**：ρ_end 取 0.85 / 0.90 / 0.95 三档，59→60 的单年降幅分别是 −4.96% / −3.47% / −1.98%，五年累计 −17.25% / −12.39% / −7.52%（85 岁 41,412 / 43,259 / 45,058 元）；三档的峰都仍在 46 岁。方法论里这句话由 `sensitivity_retirement_glide.json` 现算。
- 每户是另一张表：横轴换成户主年龄 22–85，柱高是一户人家一年的总支出，由人均表按户均人口（1 / 2 / 3 / 2 / 1.4）加总。户构成 11% 一人户 vs 七普 28%，**只作情景**；加权户均 125,690 元，对锚点 127,554 元偏 **−1.46%**。
- 校准：八类之和误差 0（机器精度）、加权总额 54,980.00 元（+0.0000%）、逐类最大偏差 0.0000%、单格最大压缩 6.09%（闸门 15%）。

## 七、分享卡片与图标（如何重出）

```bash
cd viz && python build_og.py
```

一条命令重出全部五件，数据更新后重跑即可（只读 `../data/shanghai_lifecycle.json`，不碰 `lifecycle.html`）：

| 文件 | 尺寸 | 体积 | 用途 |
| --- | --- | --- | --- |
| `og-image.png` | 1200×630 | 102,146 B | `og:image` / `twitter:image` |
| `og-image.svg` | 1200×630 | 51,602 B | 矢量底稿（与 PNG 同源，便于二次编辑） |
| `favicon.svg` | 16×16 视图 | 629 B | 浏览器标签页 |
| `favicon-32.png` | 32×32 | 807 B | 标签页 / 书签回退位图 |
| `apple-touch-icon.png` | 180×180 | 1,274 B | iOS 添加到主屏 |

**卡片构图**：左侧 60% 是字（主标题 46px 思源宋体两行、副行 17px 无衬线、`64,415` 82px 衬线 + 单位 + 一行说明），右侧 40% 是 86 根堆叠柱的剪影（无坐标轴、无注释、无网格，只有 46 岁那根顶上加了一道细横线和一条「最贵」引线），右下角一行 11px 来源说明。柱高按 `absolute` 现算，颜色直接取 JSON 的 `categories[].color`。

**为什么不是「SVG 转 PNG」**：本机没有 cairosvg，无头 Chrome 又被沙箱挡住（命名管道 `Access is denied`）。所以脚本把图形写成一份**显示列表**（rect / line / circle / text），再由两个后端分别输出：Pillow 用 2 倍超采样绘制后 LANCZOS 下采样出 PNG，另一个只写 SVG 文本。同一份列表，矢量稿与位图不会漂移。

**两个小决策**：
- 数值用 `int(v + 0.5)` 取整，不用 Python 默认的 `round()`——后者是 banker rounding，会把 64,414.5 抹成 64,414。
- 图标里的圆点在 16–32px 会和中柱顶端糊成一坨，所以小尺寸只留三根柱子；180px 的主屏图标也去掉了圆点（悬空的点看起来像气球）。标记的识别度靠三根柱子的高低差，而不是那个点。

**幂等**：无随机数、无时间戳、PNG 不写 `tEXt`，连续跑两次 `md5sum` 五个文件全部一致（已用 `md5sum -c` 验证）。

**缩略图检查**：把 `og-image.png` 缩到 300×158，标题两行与 `64,415` 仍可读，柱子仍是「中间高、两头低」的驼峰；`favicon-32.png` 降到 16×16 后三根柱子的高低关系仍可分辨（无糊字、无杂边）。
